定时计划与后台运行

工作流和任务可以离开屏幕自己跑：按计划定时执行，在后台推进，需要你时用通知找你。

三种计划类型

类型行为例子
一次性在指定时间执行一次。「今晚 23:00 备份数据库」
间隔每隔固定时长执行一次。「每 30 分钟检查一次构建状态」
每日每天固定时刻执行。「每天 07:30 生成晨报」

在「工作流 → 计划」中为工作流添加计划；到点后由系统调度器（WorkManager）唤醒执行。

后台运行与通知审批

  • 长任务运行期间，太墟会以前台服务方式保活，并在通知栏显示进度。
  • 流程走到人工审批节点时，会发送系统通知——点开通知即可批准或拒绝，不必守在屏幕前。
  • 应用被系统杀掉后，未完成的运行记录仍在；重新打开太墟可以恢复继续。

提高后台成功率的三个设置

  1. 允许通知

    否则审批通知和进度提示都收不到。

  2. 关闭太墟的电池优化

    系统设置 → 应用 → 太墟 → 电池 → 允许后台活动 / 不受限制（不同厂商叫法不同）。国产系统的「省电策略」建议设为「无限制」。

  3. 保持网络稳定

    涉及云端模型与远程仓库的计划任务，建议在 Wi-Fi 环境执行。

为什么任务没有准点执行？

Android 的后台调度是「尽量按时」而不是「绝对准时」：省电策略、息屏深度休眠、厂商自启动管理都可能把执行推迟几分钟甚至更久。这是系统机制，不是太墟出了问题。对策：

  • 完成上面三个设置；
  • 对时间敏感的任务，接受 ±几分钟的弹性；
  • 重要流程在计划后接一个「通知我结果」的节点，没收到通知就去 App 里看看。
