工具与 MCP

工具是 AI 的「手」：读文件、跑命令、开浏览器、查数据库都靠它。MCP 则是给 AI 外接更多工具的标准插口。

内置了哪些工具

预设能力
Browser多标签浏览器自动化：打开页面、读取内容、点击交互。
SQLite直接查询与操作数据库文件。
Git查看改动、提交、分支等版本操作。
WebSearch联网搜索最新资料。
CodeGraph分析代码结构，快速定位函数与引用。
APK 审计检查安装包信息与风险项。

此外，AI 始终可以使用文件读写与命令执行（在 Linux 沙箱内）这两项基础能力。

什么是 MCP

MCP（Model Context Protocol）是一个开放协议，让任意程序把自己「注册成 AI 的工具」。你可以把现成的 MCP 服务器接进太墟，比如文件系统、浏览器、笔记软件等社区工具。

添加一个 MCP 服务器

  1. 拿到服务器配置

    通常是一段 JSON 或两个关键信息：启动命令（STDIO 类型）或 URL（HTTP 类型）。

  2. 在太墟中添加

    「乾坤 → MCP / 工具」中新增服务器：STDIO 类型填命令与参数（在 Linux 沙箱内运行）；HTTP 类型填地址，支持 Streamable HTTP 与旧版 SSE，需要登录的服务支持 OAuth。

  3. 启用并验证

    保存后启用该服务器，回到智枢问一句「你现在有哪些工具？」，确认列表里出现了新工具。

按需发现
工具很多时不必担心：太墟支持按需发现，AI 会先查询有哪些工具、再挑选合适的调用，无需全部手动开启。

@ 提及：按轮裁剪工具

在消息里 @服务器名，这一轮就只带这个服务器的工具，回答更聚焦、速度更快。不带 @ 时，AI 默认可以访问全部已启用的工具。

工具不可用排查清单

  • 列表里没有这个工具：确认服务器已保存并「启用」；STDIO 类型确认命令在 Linux 沙箱里能跑通（可先到终端手动执行一次）。
  • 连接超时 / 启动慢：STDIO 服务器首次启动可能要下载依赖（如 npx 拉包），耐心等待或提前在终端预热。
  • 调用报错：查看工具调用卡片里的原始输出；多数是参数或外部服务自身的问题。
  • 审批拦截：工具调用受审批策略约束，被拦下时按提示确认即可，见审批模式与安全。
