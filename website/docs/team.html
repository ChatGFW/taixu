群聊与团队协作

把不同专长的 Bot 拉进同一个群聊，@ 它们分工干活——像带一个小团队一样推进项目。

组建一个团队

  1. 先建好成员

    提前创建几个职责清晰的 Bot：比如「主控」「开发」「评审」。

  2. 创建群聊并拉人

    新建群聊，把这些 Bot 加为成员。

  3. 说清目标

    第一句话描述整体目标与验收标准，比如：
    目标：把登录模块从 XML 迁移到 Compose。@开发 负责改造，@评审 负责检查，完成后我来验收。

@ 提及就是分工

  • 群里用 @成员名 点名，被点到的 Bot 才重点响应，避免一窝蜂抢答。
  • 不点名时，通常会由主控（或你指定的组织者）来拆解与分派。
  • 每个成员使用自己的模型与人格，强模型写代码、便宜模型跑杂活，互不影响。

独立任务：把讨论落到执行

群聊里达成一致后，可以让成员把它变成一个独立任务去执行：

  • 任务有自己的会话与状态：排队 / 运行中 / 受阻 / 已完成，在任务列表里随时查看。
  • 执行过程中的审批仍然只归你——需要确认的操作会单独弹出，见审批模式与安全。
  • 任务完成后成员会回报结果，产物（文件、提交、报告）可以直接查看。

续办：沿着原任务继续

看到回报后想改？不用重开任务，直接在原任务上补充要求（「把错误处理再补一下」），它会沿着原来的会话与上下文继续推进——这是团队协作里最省心的接力方式。

协作小贴士

  • 目标写验收标准：「可构建、测试通过」比「做好一点」有效得多。
  • 成员宁少勿多：3 个职责清晰的成员好过 8 个互相等待的成员。
  • 让主控记备忘：把分工与约定写进主控 Bot 的记忆，下次群里接着用。
