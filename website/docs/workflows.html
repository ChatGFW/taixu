可视化工作流

工作流把「一套固定流程」画成流程图：命令、AI、构建、人工审批按箭头连接，可保存、复用、定时执行。做一次，以后一键复跑。

先认识几个概念

概念解释
节点流程中的一个步骤。可以是一条命令、一个 Agent 任务、一次构建，或一个「等人工确认」的审批。
连线 / 条件步骤之间的先后关系；条件边可以让流程「通过走 A、失败走 B」。
并行互不依赖的节点可以同时执行，节省时间。
运行工作流的一次实际执行，有完整的历史记录可回看。

可用节点一览

  • Bash / 后台进程：在 Linux 沙箱里执行命令；长驻服务用后台进程节点。
  • Agent / 子智能体：让某个 Bot 或临时 Agent 干一段智能活。
  • 构建：调用工坊的 Android / Flutter 构建能力。
  • 宿主动作：通知、安装 APK 等手机端操作。
  • 人工审批：流程走到这里会暂停（并发通知），等你确认再继续。

从模板创建第一个工作流

  1. 进入「工作流」页

    从内置流程列表挑一个贴近需求的模板，创建副本。

  2. 改节点内容

    点开每个节点，把命令、提示词、目标项目换成自己的。

  3. 手动跑一次

    点击运行，观察每个节点的状态与输出，哪步不对改哪步。

  4. （可选）加定时

    满意后为它设置一次性 / 间隔 / 每日计划，见定时计划与后台运行。

新手从一个真实小场景开始
「每天早上：执行 git pull → 让 Agent 总结新提交 → 通知我」，三个节点就能体会到工作流的价值。

导入导出与分享

工作流支持 JSON 导入 / 导出：把好的流程分享给朋友，或把别人分享的 JSON 导入直接用。

中断恢复的规则

  • 运行中断（应用被杀、断电）后可沿原运行记录恢复。
  • 已经成功的节点不会重新执行，只从断点继续。
  • 中断时尚未结算的动作会先向你确认如何处理（重试 / 跳过），避免重复副作用。
长任务前先做两件事
① 允许通知；② 把太墟加入电池优化白名单。这决定了后台运行的可靠性，见定时计划与后台运行。
