审批模式与安全

太墟把 AI 当作「会真实修改文件的执行系统」来对待：哪些操作 AI 可以自己干、哪些要问你，由审批模式说了算。

三种审批模式

模式行为适合
完全访问不打扰，所有工具调用（含命令执行等）直接放行。沙箱内折腾、跑工作流、完全信任的重复任务。
询问（推荐新手）常规操作自动放行，有风险的操作弹卡征求同意。日常使用：兼顾效率与可控。
每次审批每个工具调用都等你确认。不熟悉的模型、第一次交给它重要任务时、审查 AI 行为。
还有 Plan 只读模式
计划模式下 AI 只读不写、只规划不动手，适合让它先出方案、你看过再执行。

全局与单个会话

  • 全局设置（乾坤 → 审批 / 权限）是所有新会话的默认值。
  • 会话设置可以为某个对话单独指定模式；会话自己的设置优先于全局——所以改了全局却不生效时，先检查当前会话是否单独设过。

审批长什么样

需要确认时，对话里会出现一张审批卡片：写明要执行的具体操作（比如哪条命令、写哪个文件），你可以选择允许一次、拒绝，或说明修改意见让 AI 换个做法。中断后未处理的审批会保留，恢复会话时继续等你裁决。

文件检查点与回退

  • 每轮开始前，太墟会为将要改动的工作区文件创建检查点（checkpoint）。
  • 回退（rewind）到某轮时，文件状态一并恢复；如果在恢复范围外你手动改过文件，太墟会检测冲突并报告，不会悄悄覆盖。
  • 配合对话分支，你可以放心让 AI 大胆试错，试错成本只是「回退一下」。

凭据与敏感信息的边界

  • API Key、Git Token、OAuth Token 保存在应用侧安全存储，不进入对话上下文，也不会写进工作区。
  • 请求上下文诊断面板可查看发给模型的请求内容（支持脱敏预览），只保留在内存中。
  • 仍要避免在对话里粘贴密码、私密文件内容——它们会成为模型上下文的一部分。
「完全访问」不是无边的
它免的是太墟内的审批打扰；Android 系统权限（安装 APK、无障碍、Shizuku 等）仍需逐项授权，宿主能力另有开关。
