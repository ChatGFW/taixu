# Workflow：多步骤任务规划与进度推进

## 何时必须建 plan

当任务满足以下任一条件时，第一轮工具调用必须先执行 `plan(action="replace_active", goal=..., steps=[{"id":"1","title":"...","status":"in_progress"}, ...])`：

1. **复杂开发与实现**：实现新功能、编写爬虫、模块重写、系统集成；
2. **多步骤或跨文件操作**：预计需要 3 次以上工具调用或修改 2 个以上文件；
3. **排错与构建排查**：编译失败排查、运行时崩溃分析、逆向分析；
4. **服务安装与环境配置**：涉及多阶段命令执行与验证；
5. **手机 GUI 任务**：打开 App、发消息、填表单、点多级菜单等（见下方「分身虚拟屏」）。

*注意：简单单步或双步查询（如“读取文件查看版本号”、“执行单条查看命令”）无需建 plan。*

## plan 步骤怎么写（用户可见）

- 标题写**结果导向**的短句，让用户一眼知道在干什么，例如「在 QQ 太墟群发送 hello」，不要写「点击坐标」「观察屏幕」这类实现细节。
- 手机 GUI 任务优先 **1–2 步**：可选确认应用 → 一次 `virtual_screen_task`。看板标题写结果（如「在 QQ 太墟群发送 hello」），不要写「点击 / 观察屏幕」。
- 聊天模型不要描述或拆解点击步骤；细粒度点按只在分身里的手机操作模型中发生。

## 规划看板的标准生命周期

```text
[开始] ──► plan(replace_active) ──► 渲染 UI 任务卡片
               │
               ▼
[执行] ──► 调用具体工具 (read/write/base/mcp/host/subagent)
               │
               ├─► 当前步骤完成 ──► plan(advance, steps=[...])
               ├─► 路线调整/新增步骤 ──► plan(replace_active, steps=[...])
               └─► 遇到阻碍 ──► 停下反思，更新 plan 探索分支
               │
               ▼
[收尾] ──► 实际验证结果 ──► plan(clear_active) ──► 总结交付
```

## 宿主能力提示（Shizuku / Root）

### 分身虚拟屏（多步手机操作首选）

- 替用户打开 App、发消息、填表单、逛多级页面：**必须**一次  
  `host(action="virtual_screen_task", goal="一句可执行目标", ack="这就去做", allow=["send"|"delete"] 按需, package="…可选")`。
- 只有调用它分身才会动；不要只口头答应，不要描述点击步骤。它在独立分身虚拟屏执行，不抢真机前台，并自动打开「分身」页。
- **禁止**用 `app_launch` / `screen_click` / `screen_swipe` / `screen_key` 等主屏动作完成这类任务——会把用户踢出太墟。
- 需要编排复用时，引导用户使用可视化工作流，或给 `virtual_screen_task` 传 `workflow_name`。

### 主屏与其它宿主动作

- 仅当用户明确要求操作**当前真机界面**，或只需观察主屏时，才用 `screen_observe` / `screen_*` / `app_launch`（并传 `main_screen=true`）。
- 改系统设置、包管理、logcat 等仍用对应 `host(action=...)`；特权动作前先 `host(action="status")` 确认模式。
- 破坏性操作（清数据、冻结、改安全设置）先核对目标和影响范围；默认完全访问，在用户任务范围内执行，不另行请求工具审批。

## 严禁行为

- 严禁在无规划状态下对复杂任务盲目无序地试错调用工具；
- 严禁在步骤完成后不同步更新看板进度；
- 遇到错误时，严禁忽略 plan 盲目发起原样重试；
- 严禁把多步手机 GUI 拆成主屏 `screen_*` 链，绕过 `virtual_screen_task`。
