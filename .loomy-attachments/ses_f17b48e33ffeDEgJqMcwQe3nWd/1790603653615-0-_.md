## 二、逐条详情

### 问题 1（主因）：`base` 参数被错误嵌套进 `arguments`

**报错原文**
```
工具参数校验未通过：缺少必填参数 command；不接受参数 arguments
（该工具可用参数: command、cwd、timeout_seconds）。请按工具定义修正参数后重新调用，必填字段不可省略。
```

**错误调用样本**（真实抓取）
```json
// 单层嵌套
{"cwd":"/workspace/nodes","arguments":{"command":"echo hi","cwd":"/workspace/nodes"}}
// 双层嵌套（更严重）
{"cwd":"/workspace/nodes","arguments":{"cwd":"/workspace/nodes","arguments":{"command":"echo test","cwd":"/workspace/nodes"}}}
```

**根因**
`base` 的参数 schema 是**顶层平铺**字段（`command` 必填 / `cwd` / `timeout_seconds`）。
调用时把参数误包进了一个 `arguments` 对象 → 顶层缺少 `command`，同时出现 schema 未声明的 `arguments` 字段 → 被校验直接拒绝。
（报错里 `JSON input: .....wd\": \"/workspace/nodes\"}}"` 末尾的双 `}}` 就是多套一层的铁证。）

**修正（正确写法）**
```json
{"command":"echo hi","cwd":"/workspace/nodes"}
```

**关联记忆**：已写入长期记忆 `base-tool-param-command`（revision=2）。

### 问题 2：`read` 参数被错误嵌套进 `arguments`

**报错原文**
```
工具参数校验未通过：缺少必填参数 path；不接受参数 arguments
（该工具可用参数: path、offset、limit）。请按工具定义修正参数后重新调用，必填字段不可省略。
```

**错误调用样本**
```json
{"arguments":{"arguments":{"arguments":{"path":".../BoxActivity.smali","limit":100}}}}
```

**根因**：与问题 1 同源——`read` 的顶层字段应为 `path`/`offset`/`limit`，被误包进 `arguments`。

**修正**：
```json
{"path":".../BoxActivity.smali","offset":1,"limit":100}
```

### 问题 3：`base` 参数 JSON 非法 / 空对象

**报错原文**
```
工具参数 JSON 解析失败（Unexpected JSON token at offset 512/554: Expected end of the object or comma at path: $
JSON input: .....ize' | sort -u | head -40"}）。请重新发起完整的工具调用，参数必须是合法的 JSON 对象。
```

**错误调用样本**（真实抓取）
```json
// 参数体为空对象
{"cwd":"/workspace/nodes","arguments":{}}
```
（另有长命令中因引号/转义未闭合导致 JSON 截断）

**根因**
1. 命令包含大量引号/管道/`|` 时，`command` 字符串未转义好 → JSON 截断或解析失败；
2. 空 `arguments` 对象导致顶层缺少 `command`。

**修正**：精简/转义命令字符串，或用脚本文件（`write` 落盘后再 `base` 执行）规避复杂转义。

### 问题 4：CodeGraph 后台索引未就绪（时序问题）

**报错原文**
```
CodeGraph 工具执行异常: 后台初始索引进行中: 997/3878 个文件 (25%)，请稍后重试同步或查询
```

**调用**：`use_capability(action="call", server="mcp_codegraph", tool="codegraph_explore", arguments={"query":"KillCloudInjectActivity 去云注入"})`

**根因**：首次调用触发后台全量索引，索引未完成前查询被拒。**非参数错误**。

**修正**：改用 `base` + `ripgrep`/自制脚本完成同等检索；或等待索引完成后再查询（幂等，可重试）。

### 问题 6：沙箱缺少 `file` 命令（exit 127）

**报错原文**

## 四、根因归纳

1. **唯一主因**：混淆了参数打包层级 —— 把只属于 `use_capability` 的 `arguments` 用法，错误套用到内置工具 `base`/`read` 上。
2. **诱因**：命令字符串含大量引号/管道时转义不当，导致 JSON 截断。
3. **放大因素**：失败后未先核对 schema 就原样重试 → 触发熔断。

## 五、正确参数速查（内置工具一律顶层平铺）

| 工具 | 顶层字段 | 备注 |
|---|---|---|
| `base` | `command`(必填)、`cwd`、`timeout_seconds` | 不用 `arguments` |
| `read` | `path`(必填)、`offset`、`limit` | 不用 `arguments` |
| `write` | `path`、`content` | 不用 `arguments` |
| `edit` | `path`、`oldText`、`newText` | 不用 `arguments` |
| `history_search` | `query`、`limit` | 不用 `arguments` |
| `use_capability` | `action`、`server`、`tool`、**`arguments`** | **仅此处用 `arguments`**（承载 MCP 工具参数） |

## 六、预防措施

1. 调用前先看工具 schema 的**顶层**字段名，不凭习惯套 `arguments`。
2. 牢记：`arguments` **只属于** `use_capability`（MCP 参数容器）。
3. 遇「缺少必填参数 X；不接受参数 Y」→ 直接把 Y 去掉、把 X 提到顶层，**不要原样重试**。
4. 连续 2 次同类失败即停下核对 schema，避免触发熔断。
5. 复杂命令改为「先 `write` 落盘脚本，再 `base` 执行」，规避引号转义问题。
6. 已固化到长期记忆：`base-tool-param-command`。
