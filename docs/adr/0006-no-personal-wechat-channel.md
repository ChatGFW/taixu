# ADR-0006 不接个人微信渠道

- 状态：已接受
- 日期：2026-11-17
- 决策域：渠道 / 合规
- 关联：`docs/TOBS_COMPARISON.md` 第 12 项
- 取代：无
- 被取代：无

## 背景

Tobs 有一套个人微信扫码链路（iLink/ClawBot 类）：扫码登录、复用个人号会话收发消息。太墟目前没有第三方 IM 渠道，最大功能空位在企业协作侧。

个人微信没有面向第三方的官方机器人协议；扫码链路依赖非官方客户端协议，存在封号、账号连带风险，也不满足企业场景的合规要求。

## 选项

1. **照抄个人微信扫码链路**：被拒。封号与合规风险由用户承担，且不稳定。
2. **不做任何 IM 渠道**：被拒。企业协作是真实需求，飞书/企微/公众号都有官方 API。
3. **只做官方渠道，个人微信不碰**：采纳。

## 决策

- 渠道优先级：飞书 → 企业微信/公众号 → QQ 官方机器人 → Slack/Discord。
- 每个渠道一个 Provider 包，声明能力（文本/图片/文件/线程/撤回），回复走原来源线程，幂等 outbox + 对账。
- 明确不做：个人微信扫码、个人号协议复用、任何需要保存个人账号密码的登录方式。
- 若未来微信开放官方个人机器人 API，再单独立 ADR 重新评估，不在本决策下偷偷接入。

## 影响

- 正面：合规边界清晰；渠道故障可归因到具体 Provider。
- 代价：无法覆盖只用个人微信的交流场景；这是产品取舍，不是能力缺失。
- 回滚：无代码改动。

## 验收

渠道 Provider 合入时检查：无个人号登录代码、无扫码后保存的会话凭据；能力声明与实现一致；回复线程与幂等键有测试。
