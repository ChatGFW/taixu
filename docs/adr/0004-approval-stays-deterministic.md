# ADR-0004 审批以确定性策略为基线，模型审批官单独立项

- 状态：已接受
- 日期：2026-11-17
- 决策域：审批 / 安全边界
- 关联：`docs/PLUGIN_HARNESS_EXTENSIONS.md`、`docs/SECURITY_SURFACE.md`、`docs/TOBS_COMPARISON.md` 第 10 项
- 取代：无
- 被取代：无

## 背景

Tobs 的 Reviewer 只有两种输出：`allow` / `ask-human`，且默认不阻断。太墟现状是纯确定性策略：`TrustedToolRiskPolicy`、`McpPolicyRisk`、`AnnotationEscalation`、`SessionApprovalGrants`，外加事后审计 `ApprovalAuditRecorder`；**没有模型审批官**。

把「Reviewer 两态」当成本轮对齐项，会引入一个新的模型判断层，而不是对齐既有能力。

## 选项

1. **直接引入模型 Reviewer，替换确定性策略**：被拒。误拒会停摆，误放会穿透安全边界，且成本与超时都未定义。
2. **模型 Reviewer 与确定性策略并行，任一拒绝即拒**：被拒。等于把误拒率相乘，收益不明。
3. **确定性策略保持基线，模型审批官作为独立能力立项**：采纳。

## 决策

本轮不改审批链路。模型审批官若要做，必须先把四件事定清楚，再单独立 ADR：

- 模板：给模型看什么（工具名、参数摘要、来源 provenance、会话上下文）。
- 超时：模型不返回时按 `ask-human` 还是按确定性策略放行。
- 成本：每次审批的 token 预算与触发频率上限。
- 误拒入口：用户被误拒后如何一键改判，且该改判要进审计。

在四件事落定前，`harness/approval` 维持「确定性策略 + 事后审计」，不新增模型判断。

## 影响

- 正面：安全边界不因对齐而退化；审批延迟与成本可控。
- 代价：复杂场景仍依赖人工确认，无法自动放行「看起来安全」的工具调用。
- 回滚：无代码改动，本身就是「不实施」。

## 验收

无新增验收项；后续若立项，以「误拒可改判且留痕」为第一条验收。
